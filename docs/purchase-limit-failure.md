# 구매 한도 실패 응답

상품 확보 시 확정된 구매량과 새 요청 수량의 합계가 계정별 한도를 넘으면 HTTP 409의 `PRODUCT_PURCHASE_LIMIT_EXCEEDED`를 반환합니다. 실제 재고 부족은 기존 `PRODUCT_STOCK`을 유지합니다.

상품 서비스는 상품 행 잠금 안에서 계산한 `purchaseLimit`과 `remainingPurchaseQuantity`를 반환합니다. 주문 서비스는 확정 업무 거절로 처리해 결제를 시작하지 않고 실패 코드와 두 숫자를 저장하며, 주문 생성과 체크아웃 폴링 응답에 동일하게 제공합니다.

프론트는 남은 수량이 0이면 확인만 표시하고 일부 남으면 해당 수량 이하에서 구매를 허용합니다. 숫자가 없거나 유효하지 않으면 공통 한도 안내를 사용합니다. 상품 상세의 `perAccountLimit`에는 계정의 누적 구매량이 없으므로 사전 수량 선택은 총 한도만 검사할 수 있습니다.

배포 시 OrderCommandService의 V7 마이그레이션과 신규 코드 허용을 먼저 반영하고 FE를 반영한 다음 ProductCommandService에서 신규 오류를 활성화합니다. 신규 오류를 구분하지 못하는 구버전 주문 서비스와 상품 서비스의 조합을 피해야 합니다. 이 변경은 develop 머지까지만 수행하며 운영 배포는 수행하지 않습니다.
